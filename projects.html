Active Rust Bevy MIT OR Apache-2.0

sail

A sailing simulator in the spirit of a long-haul truck sim: you skipper a small cruising sloop and the point is the passage, not the race. The dynamics are the whole requirement — apparent wind, sail trim, heel and righting moment, leeway, the hull-speed wall, rudder stall, weather helm — rather than a wind arrow and a speed multiplier.

Four crates, split so the physics never learns about the renderer: sail-core is the dynamics alone, sail-app is the only crate that knows Bevy 0.20 exists, sail-net carries boat-to-boat traffic and must build for the smallest VM anyone rents, sail-bios the front end. The project site and manual are generated from the repository, key list included, so they cannot drift from the program.

Repo: github.com/kapoost/sail · Site + manual: kapoost.github.io/sail · current tag v0.1.19

In production AdCP TypeScript

purrsonality-seller-agent

Production-grade AdCP seller agent reference implementation. Bun + @adcp/sdk 13.0.4 + Postgres + Fly.io. Faza 1 of the seller discovery roadmap (adcp-capabilities.json + RFC 9728) shipped 2026-06-09. Phase-A ad server attributes live impressions to the correct media_buy_id via reverse creative-assignment lookup, so get_media_buy_delivery returns real numbers instead of zeros. Fly machines run auto_stop=suspend — snapshot wake ~200ms instead of a 3s cold boot.

AAO compliance on 3.1, as graded in July 2026: Product Discovery, Creative Management, Reporting & Delivery, Error Handling PASS. Core Protocol + Media Buy Lifecycle PARTIAL — one pagination and one creative-reuse scenario were blocked on SDK runtime-projector gaps. Both upstream issues have since closed (adcp#5723, #5797); the grade above predates that and has not been re-run here. The badge reflects the registry's current view.

Repo: github.com/kapoost/purrsonality-seller-agent · Live: purrsonality.rocketscience.pl

In production AdCP TypeScript

abzu

AdCP buyer-side orchestrator: get_products fan-out over multiple sellers, governance gate (check_governance → create_media_buy → report_plan_outcome), and sync_creatives + update_media_buy assignment so served impressions link back to the caller's buy. Ships with a static GUI (abzu-gui) covering the full linear thread — Jordan reviewer → Sam operator → Publisher operator → Sponsor read-only. Twelve real sellers wired in from the AAO registry, with a failure classifier that reports why a seller didn't respond (auth, timeout, unreachable, version, protocol) instead of dumping every failure into "incompatible".

AAO compliance: Abzu Orchestrator (buying) Core Protocol 32/32 silent on 3.1. Governance side (Abzu Governance) passes Core + Campaign Governance + Error Handling 6/7 on 3.1.

Repos: abzu-orchestrator · abzu-governance · abzu-gui · Live: abzu.rocketscience.pl

Active Go Indie web

humanMCP

Personal MCP server. Publish poems, images and structured data with Ed25519 signatures so any AI agent can verify provenance offline. Session gate uses a fragment of Polish poetry as the access code. The running instance exposes 43 tools, 24 expert personas and 35 skills, plus server-side advisory pipelines (run_narada, prepare_narada) that let an agent convene a panel instead of role-playing one from memory.

Two trees, deliberately: humanmcp is the instance deployed at kapoost.humanmcp.net, and humanmcp-go is the packaged open-source variant anyone can self-host (also listed on Smithery).
